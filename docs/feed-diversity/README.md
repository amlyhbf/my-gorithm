# 추천 피드 다양성 개선 — 개발 검토본

> 최신 전체 검증 결과는 [VALIDATION.md](VALIDATION.md)를 참조. 아래 실행 상태는 이번 전체 검증 이전의 개발 기록이며, 현재 빌드·추천 단위 8개·피드 브라우저·인트로 11개 검사는 통과함.

기준: `feat/intro-web-integration`에서 파생한 `feat/feed-diversity-v1`.
기존 운영 사이트 및 Vercel V4.4 테스트 사이트는 변경하지 않았음.

## 해결하려는 문제
- 고정 초기 순서로 매번 같은 콘텐츠가 노출됨.
- 새로고침이 등록된 자료를 섞기만 하며 이미 본 카드가 다시 나옴.
- 특정 분야의 등록 카드가 12개보다 적을 때 같은 카드를 반복하여 12개를 채움.
- 12개 이후 콘텐츠를 발견할 별도 탐색 동선이 없음.

## 설계
- `feed-engine.js`: 순수 함수로 용량 제한을 고려한 가중 할당, 중복 없는 선별, 최근 노출 카드의 우선순위 하향을 수행함.
- 초기 피드는 종전대로 **최대 12개**. 데이터 풀에서 12개가 모자라면 억지로 중복하지 않음.
- 화면 아래 **「새로운 추천 더 보기」**를 누를 때 아직 표시하지 않은 카드를 최대 12개 추가함. 모두 소진하면 버튼 숨김.
- `mamgorithm_recent_feed_v1` 로컬 저장 키에 최근 노출된 콘텐츠 ID 순서를 저장하여 재방문 및 새로고침 때 아직 보지 않은 카드가 먼저 나옴. 데이터가 소진되면 오래전에 보았던 카드부터 다시 추천될 수 있음.
- 사용자의 관심도가 0인 분야는 추천하지 않음. 선택한 콘텐츠 유형(전체/영상/기사)을 유지함.
- 일부 분야에서 카드가 부족해지면 다른 활성 분야의 남은 카드로 추천 분량을 채우되, 사용자의 가중치를 고려함.
- 「내 알고리즘 분석」의 카드 수는 *현재 실제로 표시된 수*를 반영함. 비율 표시에는 사용자가 설정한 가중치 비율을 유지함.

## 변경된 파일
- `feed-engine.js` (신규)
- `script.js`
- `index.html`

- `tests/feed-engine.test.mjs` (신규)

기존 `data.js`, `firebase.js`, `intro.js`, `intro.css` 및 정적 인트로 자산은 수정하지 않음.

## 단위 테스트
```bash
npm run test:feed
```
검증 대상: 12개 균형 배분, 12→12→8 총 32개 중복 없이 탐색, 재방문 새 카드 우선, 공부 100% 선택 시 8개만 표시, 품절 분야 재할당, 영상 필터, 전체 제외, 중복 ID 제거, 재방문 이력.

## 실제 실행한 추천 엔진 테스트

2026-10-30에 GitHub의 `feed-engine.js`와 `tests/feed-engine.test.mjs`를 Git blob SHA로 대조한 다음 Node.js 환경에서 **7개 단위 테스트를 실제 실행하여 모두 통과**함. 별도의 추가 검증으로 가중치·카테고리 재고·요청 수를 무작위로 조합한 10,000개 사례에서 정원 초과·중복·0% 카테고리 노출이 없음을 확인함. 이 무작위 검증은 독립적으로 실행한 검사이며 GitHub에 자동 테스트로 저장된 것은 아님.

기존 저장소의 전체 Vite 빌드 및 Playwright 통합 검증은 아직 실행하지 않았음.

## 브라우저 검증 체크리스트 (운영 반영 전 필요)
1. 시크릿 창에서 첫 방문 인트로→온보딩→피드로 이동
2. 균형 모드/전체: 초기 12개, 더 보기 후 24개, 다시 더 보기 후 32개 확인
3. 어떤 페이지에도 동일한 콘텐츠 ID가 중복되지 않는지 확인
4. 새로고침, 탭 전환, 보관함 저장, 관심도 조절 후 정상 카드 표시 및 북마크 보존
5. 공부만 100%, 나머지 0%: 공부 카드 8개, 추가 버튼 숨김
6. 영상/기사 필터 변경과 0% 분야의 제외 확인
7. 모바일/PC 및 라이트/다크에서 더 보기 버튼 UI 확인
8. 사이트 재방문 시 최근에 본 카드가 앞쪽에 반복되는 빈도가 줄었는지 확인
9. 기존 인트로 자동화 `npm run test:intro`, `npm run build` 수행

## 추가한 브라우저 자동화

`tests/feed.browser.cjs` 파일과 `npm run test:feed:browser` 명령을 추가했음. 이 브라우저 테스트는 네트워크를 같은 원본으로만 제한하고, 콘텐츠 12→24→32·재방문·셔플·필터·학습 집중·프리셋·북마크를 검증하도록 작성됨. **테스트 코드를 작성한 것과 실제 통과한 것은 별개이며, 아직 실행 결과를 확인하지 못함.**

## 검증 상태
추천 엔진의 Node.js 단위 테스트 **7개 실실행 통과**, 추가 무작위 사례 10,000개 검사 통과.
이 문서 작성 시점에는 **Vite 전체 빌드 및 실제 브라우저 통합 테스트를 아직 수행하지 않았음**.
운영 배포, `main` 병합, Vercel 재배포를 수행하지 않음.

## 한계
새로운 콘텐츠를 자동 수집하지 않으므로 등록된 32개가 전부 소진되면 새로운 콘텐츠를 더 제공할 수 없음.
카드 자료를 추가하려면 링크·설명·카테고리 등을 별도로 검증해 `data.js`에 반영해야 함.
