## 실제 추천 계산

script.js의 실제 calculateAllocation/buildFeedList와 data.js를 격리된 Node VM에서 실행한다.
새 타이밍의 모든 관심도 상태에서 실제12개·영상대표6개 배정과 순서를 재검사한다.
시작50/50/50/50, 최종100/30/20/50. 최종 실제 배정6/2/1/3.
6개 출력은 실제12개 출력에 같은 상대 순서로 들어가는 대표 목록이며 서비스 카드 수는 변경하지 않는다.
조절 중에는 이전 유효 결과를 유지하고 목표 관심도 계산을 마친 뒤 새 결과를 표시하는 연출이다.

## 렌더링과 재사용

공식 --screenshot/--advance로 1/60초 단위 프레임을 만들고 FFmpeg는 H.264 압축 및 비교 편집에 사용한다.
저FPS 영상 배속·보간·중복 프레임 변환으로 최종60FPS를 만들지 않는다.
첫2초는 기존 네이티브120프레임/테마를 재사용하며, 보호된 숫자 키와 각 테마 1.0/1.983초의 원본
전체 키 네이티브 캡처가 기존 PNG와 RGB 완전 일치함을 확인했다.

나머지는 렌더 전용 사본에서 해당 프레임의 숫자 보간 구간만 남겨 CLI 컴파일 비용을 줄인다.
원본/최종 .riv에는 전체 키가 있다. 시각·원래 키값·베지어·공식 렌더러는 유지한다.
원본/사본 네이티브 A/B 10개 중8개는 RGB 완전 동일. 두 테마2.75초에서 각9픽셀(전체의0.00174%)에
채널 최대15/16 차이가 있다. 가장자리의 작은 차이도 숨기지 않고 unchanged-intervals.json에 남긴다.
재사용 증거와 이 사본 비교를 혼동하지 않는다.

## UI·모바일

29px 눈금을 줄이지 않고 카드 높이136→160, 행 간격160→176, 눈금 중심–하단6→30px로 조정했다.
트랙 중심–눈금 중심46px와 브랜드 위치·스타일은 유지한다. 실제 MP4 마지막 프레임 추출물로 최종 확인한다.
360×640/390×844/430×932의 contain-fit 이미지는 정적 가독성 검토용이다.
물리 스마트폰·브라우저 성능 테스트를 했다고 주장하지 않는다. 최종 축소 눈금은 약8–9.5px로 작은 보조 글자다.
웹 연결 시 실제 기기에서 보조 눈금의 크기를 다시 확인해야 한다.

## 실제 시각 검토 완료

저해상도 테스트를 연속 스틸/콘택트시트로 확인하고 초반 핸들·카드 경로를 수정했다.
인터랙티브 영상 플레이어는 제공되지 않는 환경이므로 영상을 실시간으로 시청했다고 주장하지 않는다.
최종 MP4에서 추출한959번째프레임(0부터 계산)을 열어 네 카드 모두 눈금이 테두리 안에 위치하고,
손잡이와 눈금 사이 간격이 유지되는지 확인했다. 비교C 확대 이미지에서도 확인한다.
360/390/430px contain-fit 시안을 두 테마로 만들었고 주요 글자·UI 잘림은 없다.
브랜드와 피드의 주요 제목은 읽을 수 있다. 마지막 보조 눈금은 약8–9.5px로 작으므로
디자인 승인 때 실제 스마트폰에서 확인할 사항으로 남긴다. 물리 기기 성능은 미검증이다.

비교A는 이전0–6초와 신규0–3.5초를 원래 속도로 보여주며 짧은 쪽은 끝 프레임을 유지한다.
비교B는 이전9.6–13.3초와 신규7.5–13.3초를 원래 속도로 비교한다. 비교물의 명시적 정지와
실제16초 최종 MP4를 구분한다. 비교A/B도60FPS/390프레임/348프레임으로 디코딩 검사를 통과했다.

실제 배포·웹 연결·기존 브랜치 병합·원본 저장소 수정은 수행하지 않았다.
