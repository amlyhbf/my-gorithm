# 맘고리즘 시네마틱 인트로 V4

원본 저장소·운영 사이트·V1–V3를 수정하지 않은 독립 제작 프로젝트입니다.
작업 저장소 `amlyhbf/my-gorithm`, 브랜치 `feat/rive-intro-v4`.

## 먼저 보기

- `preview/intro-v4-dark.mp4`: 모바일 주 결과물. 1080×1920 / 60 FPS / 16초.
- `preview/intro-v4-light.mp4`: 같은 디자인 시스템의 라이트 버전. 1080×1920 / 60 FPS / 16초.
- `preview/intro-v4-dark.gif`, `intro-v4-light.gif`: 빠른 확인용 360×640 / 15 FPS 미리보기.
- `preview/storyboard.png`: 실제 최종 Rive 렌더 프레임으로 구성한 장면 요약.
- `preview/scene-*.png`: 장면별 Full HD 이미지.
- `preview/draft-full-dark.mp4`: 최종 제작 전 전체 흐름을 검토한 360×640 / 15 FPS 시안.
- `preview/final-dark-info.json`, `final-light-info.json`: 실제 파일 사양·SHA-256.
- `preview/logic-verification.json`: 사이트 추천 함수·카드 ID·모핑 구조 검사 결과.
- `preview/frame-audit.json`: 프레임 수·크기·시간대별 이미지 고유 수 검사.

GIF는 타이밍 단위와 색상 수에 한계가 있어 움직임과 색상의 최종 판단은 MP4로 해주세요.
각 최종 MP4는 Rive CLI에서 시각을 1/60초씩 진행시키며 렌더링한 서로 다른 시점의 PNG 960장으로 만듭니다.
저해상도 영상을 늘리거나 프레임을 보간하지 않습니다. 마지막 정적 읽기 구간의 동일한 프레임은 의도한 유지 장면입니다.

## 기획: 혼돈 → 질서 → 나만의 알고리즘

| 장면 | 시간 | 연출 |
| --- | --- | --- |
| 01 관심사의 탄생 | 0–3초 | 네 관심사가 다른 궤적·형태·속도로 등장. 취미는 작은 조각이 합류 |
| 02 자유와 교차 | 3–6초 | 세로 화면을 가로지르는 궤적, 상호 교차, 곡선·방향성 잔상 |
| 03 혼돈에서 질서 | 6–10초 | 같은 8개 곡선 꼭짓점이 큰 리본·물결을 거쳐 슬라이더 트랙으로 정돈. 조절 손잡이가 분리되어 자리 잡음 |
| 04 알고리즘 통제 | 10–13초 | 독립 관심도 조절 → 피드 비율·12장 추천 카드의 구성 변화 |
| 05 브랜드 완성 | 13–16초 | 추천 요약을 정리하고 UI를 아래로 이동, 제목·보조 문구를 약 2초 이상 안정적으로 유지 |

씬 03의 모핑은 약 4초를 차지합니다. V3의 시간을 늘린 편집본이 아니라 새로운 패스·궤적·추천 결과 장면을 가진 RML입니다.
레퍼런스 YouTube는 환경의 프록시에서 CONNECT 403으로 차단되어 직접 시청하지 못했습니다.
사용자가 설명한 공간 활용·교차·과감한 모핑·속도 대비를 제작 기준으로 삼았습니다.

## 실제 사이트를 분석해 적용한 디자인

- `style.css :root`: 라이트 배경 `#F8FAFC`, 카드 `#FFFFFF`, 본문 `#0F172A`, 보조 문구 `#64748B`.
- `body.dark-mode`: 다크 배경 `#090D16`, 카드 `#0F172A`, 본문 `#F8FAFC`, 보조 문구 `#94A3B8`.
- `data.js CATEGORY_META`: 공부 `#4F46E5`, 기술 `#0284C7`, 문화 `#BE185D`, 취미 `#059669`.
- `index.html`에서 로드하는 Pretendard Variable v1.3.9의 공식 폰트로 600·800 굵기의 필요한 글리프를 추렸습니다. 원본 폰트와 라이선스는 기존 V3 폴더에 보존되어 있습니다.
- 실제 `input[type=range]`: 독립 0–100, step=5. 6px 트랙, 22px 흰 원형 손잡이, 3px 분야색 테두리의 비율을 영상 크기로 확장했습니다.
- 카드 배경·얇은 테두리·둥근 모서리를 같은 테마 토큰으로 적용했습니다. 영상 속 작은 추천 카드는 실제 썸네일·제목을 복제한 것이 아닌 분야별 요약 표현입니다.
- 어두운 테마를 단순 반전하지 않고 두 테마의 배경·카드·본문·보조 텍스트·경계 토큰을 각각 사용합니다.

색상은 `design-tokens.json`에 분리했습니다. 현재 파일은 Dark/Light 아트보드 선택 방식이며,
사용자의 저장 테마를 자동으로 읽는 웹 연동은 구현하지 않았습니다.
사이트의 실제 테마 선택은 `body.dark-mode`와 `localStorage['mamgorithm_theme_v2']`를 사용합니다.

## 실제 추천 알고리즘과의 일치

`script.js`의 `calculateAllocation`, `seededShuffle`, `buildFeedList` 원문과 실제 `CONTENT_DATA`를
격리된 Node VM에서 실행해 타임라인의 22개 조절 상태를 만들고 다시 검증했습니다.
브라우저 사용자 상태·Firebase에 접근하거나 기존 함수·데이터를 변경하지 않았습니다.

- 시작 관심도: 50 / 50 / 50 / 50 → 추천 3 / 3 / 3 / 3장.
- 최종 관심도: 100 / 30 / 20 / 50 → 피드 비율 50 / 15 / 10 / 25%.
- 최종 12장: 공부 6 / 기술 2 / 문화 1 / 취미 3장.
- 카드 수는 실제 최대 잔여수 계산, 표시 퍼센트는 실제 `Math.round` 계산을 사용합니다.
- 12개 타일의 분야와 순서는 실제 `buildFeedList`가 선택한 카드 ID의 순서를 따릅니다.
- 정수 관심도는 5% 단위를 지킵니다. 시각적 조절 이동은 Rive 키프레임으로 연결하며, 영상의 시연 값이 사용자 설정에 저장되지는 않습니다.

세부 상태·실제 카드 ID·제목은 `logic-snapshots.json`에 있습니다.
최종 장면에 카드를 요약해 보여 주는 것이며 실제 콘텐츠 카드 UI 또는 사용자 상호작용을 구현한 것은 아닙니다.

## 모핑과 효과의 실제 구현 범위

각 관심사의 본체는 `Shape → PointsPath(isClosed=true) → CubicDetachedVertex × 8`입니다.
장면 전반에 걸쳐 이 객체를 유지하면서 x/y, in/outRotation, in/outDistance를 키잉해 둥근 덩어리·리본·물결·직선 캡슐로 바꿉니다.
UI에서 별도 Rectangle로 몰래 교체하거나 본체를 숨기지 않습니다.
동일한 패스가 완성 후에도 실제 관심도에 맞는 채워진 트랙 길이를 표현합니다.
손잡이는 본체에서 분리되어 흰색과 분야색 테두리로 변하는 별도 연속 경로입니다.
연결선은 실제 CubicDetachedVertex의 곡선이 펴지며 TrimPath로 드러나는 네이티브 벡터입니다.

지원·검증한 효과: 2D 이동·회전·변형, 시차, 패스 모핑, 투명 잔상, RadialGradient 글로우, 짧은 조각 합류.
구현하지 않은 효과: 물리 기반 입자, 실제 3D 원근 카메라, 셔터 기반 모션 블러.
방향성 잔상을 실제 움직임 흐림으로 주장하지 않습니다. Feather는 이전 환경 점검에서 거친 경계가 보여 사용하지 않았습니다.
배경음·효과음은 요청되지 않았으며 MP4에 오디오 트랙은 없습니다.

## 원본·런타임 파일·영상의 구분

- `scene.rml`: 편집 가능한 네이티브 Rive 원본, 두 테마·각 60 FPS × 960프레임.
- `rive.yaml`: 프로젝트 설정.
- `build/intro-v4.riv`: 공식 CLI `--once`로 실제 빌드하고 로컬 런타임 캡처에 사용한 파일. 배포용 게시나 로그인은 실행하지 않았습니다.
- `.riv`에는 실행 스크립트가 없습니다. 웹 런타임·해당 사이트 연결 테스트는 아직 하지 않았으므로 웹 통합 완료로 주장하지 않습니다.
- Editor용 `.rev`는 로그인 필요로 내보내지 않았습니다. RML은 바로 수정할 수 있습니다.
- MP4/GIF는 확인용 렌더 영상이며 Rive 편집 파일이 아닙니다.

## 재현 방법

저장소 루트에서:

```bash
./tools/rive animation/intro-v4 --verify
./tools/rive inspect animation/intro-v4 --summary
python tools/verify-rive-v4.py
python tools/render-rive-v4.py draft
python tools/render-rive-v4.py final
python tools/review-rive-v4.py
```

생성 스크립트 `tools/create-rive-v4.py`는 사이트 색상·함수·폰트에서 RML을 다시 만듭니다.
직접 수정한 RML이 있다면 먼저 보존하세요. Python FontTools/Brotli는 기존 환경 도구를 사용합니다.
Rive는 공식 1.8.0, 실행 도우미는 `tools/rive`입니다.

전체 시안으로 흐름을 먼저 검토하고 수정한 뒤 최종본을 렌더링했습니다.
5개 CPU를 확인했고 최대 3개 네이티브 캡처 작업자로 제한했습니다.
작업자마다 별도 RML·출력 경로를 써 병렬 빌드끼리 파일을 덮어쓰지 않습니다.
고해상도 프레임·임시 빌드 폴더는 Git에서 제외하고, 결과물과 실제 `.riv`만 보관합니다.

## 연결 전 확인 사항

디자인 승인 후 별도 작업에서 실제 Rive 웹 런타임 호환성·성능, 반응형 레이아웃과 safe-area,
첫 방문 키, 건너뛰기·다시 보기, 종료 후 기존 관심도/피드 화면 이동, 로딩 실패·타임아웃 폴백,
저장 테마 선택, `prefers-reduced-motion` 정적 대체, 포커스 복구를 구현·검증해야 합니다.
MP4를 강제로 cover 확대하지 않고 contain과 사이트의 중앙 제한 폭을 우선 검토합니다.
16초는 V4 작품 검토용 길이입니다. 실제 첫 방문 UX에 적용할 때 건너뛰기 제공과 노출 정책을 함께 검토해야 합니다.
현재 인트로는 웹사이트·기존 추천/북마크/설정·Firebase와 연결되어 있지 않습니다.

### 최종 윤곽 수정과 출력 재사용

자체 검토 중 초반 둥근 도형의 작은 곡률 돌기를 수정했습니다.
32개 변경 속성은 7.5초 이후 키프레임이 동일함을 검사했고, 두 테마의 8·10·13·16초를
현재 소스로 실제 렌더링해 기존 프레임과 RGB 픽셀 차이 0을 확인했습니다.
`preview/cache-verified.json`에 증거를 남겼습니다.
검증된 8초 이후의 원래 네이티브 프레임은 유지하고, 초반 8초는 60FPS 네이티브 렌더를 다시 수행했습니다.
전체 MP4/GIF는 이 최종 프레임들로 다시 인코딩했습니다.
`render-rive-v4.py final`은 전체를 처음부터 만들고, `refine` 모드는 해당 소스 해시와 A/B 증거가 있을 때만 이 재사용 절차를 허용합니다.

실제 사이트의 그림자는 라이트 카드 `rgba(15,23,42,0.05)`, 다크 카드 `rgba(0,0,0,0.2)`이며,
영상은 같은 토큰의 카드·테두리와 제한된 방사형 빛으로 깊이감을 정리한 표현입니다. DOM의 그림자 필터를 그대로 복제한 것은 아닙니다.
추천 시나리오는 실제 초기 설정과 같은 `contentType=all`, `shuffleSeed=0`, `feedSize=12`를 사용합니다.
