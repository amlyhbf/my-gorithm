## V2에서 달라진 점

- 모바일 전용 2×2 관심 분야 배치에서 네 줄의 UI로 변환합니다. 가로 영상을 자르거나 늘리지 않습니다.
- 실제 서비스처럼 네 분야를 독립적으로 0~100%, 5% 단위로 조절합니다.
- `관심도 값`과 합계로 정규화한 `피드 비율`을 구분합니다. 네 관심도 합계가 100%여야 한다는 잘못된 제약을 제거했습니다.
- 공부(책), 기술(칩), 문화(음표), 취미(잎)의 간결한 Rive 벡터 아이콘을 추가했습니다.
- 연결선은 결합 단계에만, 낮은 강도의 분야색 빛은 조절 완료 순간에만 표시합니다.
- Rectangle의 크기·모서리·색상 키프레임으로 도형이 카드가 됩니다. 제자리 축소나 컷 전환으로 대체하지 않습니다.
- 전체 4.5초로 늘리고 최종 브랜드를 약 1초 읽을 수 있게 유지합니다.
- 사이트의 Pretendard 글꼴과 테마 토큰을 사용합니다.

## 코드 분석으로 확인한 사이트 사양

- `style.css` `:root`: 라이트 배경 `#F8FAFC`, 카드 `#FFFFFF`, 주 텍스트 `#0F172A`, 보조 텍스트 `#64748B`.
- `style.css` `body.dark-mode`: 다크 배경 `#090D16`, 카드 `#0F172A`, 주 텍스트 `#F8FAFC`, 보조 텍스트 `#94A3B8`.
- `data.js` `CATEGORY_META`: 공부 `#4F46E5`, 기술 `#0284C7`, 문화 `#BE185D`, 취미 `#059669`.
- `index.html` `#onboardingOverlay`: 상단의 정보용 추천 비율 게이지와 네 독립 슬라이더를 표시합니다.
- `script.js` `renderOnboarding`: `type=range`, min=0, max=100, step=5. 분야색 채움, 흰 손잡이, 분야색 손잡이 테두리.
- `style.css` `.channel-range-input`: 6px 트랙, 22px 흰 원형 손잡이, 3px 분야색 테두리, 드래그 중 1.15배. V3에서는 이 비율을 모바일 출력 크기로 확장합니다.
- `style.css` `.onboarding-channel-card`: 카드 배경·1px 테두리·12px 모서리. V3에서는 30px 모서리로 출력합니다.
- `script.js` `calculateAllocation`: 관심도/관심도 합계로 비율을 계산하고, 표시 비율은 `Math.round`입니다. 카드 수 분배에만 최대 잔여수 방식을 씁니다.
- `script.js` 테마 토글: `body.dark-mode`와 `localStorage['mamgorithm_theme_v2']`의 dark/light 문자열을 사용합니다. 저장된 dark가 없으면 초기 상태는 라이트입니다. OS 테마 자동 추종이 구현됐다고 가정하지 않습니다.
- 사이트의 기본 Pretendard Variable v1.3.9를 공식 배포처에서 받아 600·800 굵기의 필요한 글리프만 추렸습니다. 라이선스는 `assets/Pretendard-LICENSE.txt`에 보존합니다.

이번 V3에서는 이전 인트로 배경 `#0B1020`과 별도 강조색 `#589CFF` 대신 사이트의 실제 토큰을 사용합니다.
디자인 구조를 정리해 인트로용 정보 밀도와 간격을 조정했으며, 실제 DOM 화면의 픽셀 단위 복제는 아닙니다.

## 타임라인

| 시간 | 장면 |
| --- | --- |
| 0–1초 | 네 방향에서 관심 아이콘·분야색 도형 등장, 안정화 |
| 1–2.2초 | 연결선으로 시스템 형성, 도형이 네 줄 카드·컨트롤로 변화 |
| 2.2–3.5초 | 공부·기술·문화 관심도 조절, 네 정보용 게이지 구간과 피드 비율 갱신 |
| 약 3.3–4.5초 | 제목·보조 문구 등장, 미세한 완료 피드백, 마지막 상태 유지 |

취미는 50%를 유지해 다른 분야를 조절해도 독립 관심도는 자동으로 바뀌지 않음을 보여 줍니다.
관심도는 `50/50/50/50 → 80/65/35/50`, 최종 추천 비율은 `35/28/15/22%`입니다.
인트로 속 조절은 시연 타임라인이며 실제 포인터 입력이나 사이트 설정 쓰기를 구현한 것은 아닙니다.

## 모바일 안전영역과 PC 확장

정적 주 콘텐츠는 가로 약 120–960px, 세로 약 340–1440px에 배치했습니다.
상하단의 노치·브라우저 UI·향후 건너뛰기 버튼 공간을 비워 두며, 진입 도형은 화면 밖에서 시작합니다.
360×640, 390×844, 430×932 확인 이미지에서는 전체 아트보드를 contain 배치합니다.
PC도 사이트처럼 중앙의 제한된 너비에 세로 구성을 유지하고 주변을 선택 테마 배경으로 채우는 방식을 권장합니다.
`cover`로 화면을 채우면 글자나 UI가 잘릴 수 있으므로 권장하지 않습니다.
이 단계의 확인 이미지는 정적 배치 검토이며 실제 기기·웹 브라우저 통합 검증을 대체하지 않습니다.

## 다시 빌드·수정하기

저장소 루트에서:

```bash
./tools/rive animation/intro-v3 --verify
./tools/rive inspect animation/intro-v3 --summary
./tools/rive animation/intro-v3 --once
python tools/render-rive-v3.py
```

`scene.rml`을 직접 편집할 수 있습니다. `python tools/create-rive-v3.py`는 원본을 다시 생성하므로 수작업 수정본이 있다면 먼저 보존하세요.
생성 스크립트는 Python FontTools와 Brotli를 사용합니다. Brotli는 `.rive-tools/python`에 설치했습니다.
다른 환경에서 생성 스크립트를 사용할 때는 `python -m pip install --target .rive-tools/python brotli==1.2.1`로 준비할 수 있습니다.
현재 CLI는 공식 Rive 1.8.0입니다. `tools/install-rive.sh`와 `tools/rive`를 재사용합니다.

## 실제 웹사이트 연결 전 승인할 사항 — 아직 구현하지 않음

1. 다크·라이트 디자인, 4.5초 속도, 최종 문구·시연 관심도 확인.
2. 호스트에서 실제 저장 테마를 먼저 읽고 Dark/Light 아트보드와 정적 화면을 선택. MP4 하나가 자동으로 테마를 바꾸는 구조는 아닙니다.
3. 인트로 전용 첫 방문 키를 따로 설계. 기존 `mamgorithm_onboarded_v2`를 재사용해 관심도 설정을 건너뛰는 부작용을 만들지 않기.
4. 건너뛰기·다시 보기는 접근 가능한 DOM 버튼으로 구현. 종료·건너뛰기·오류가 같은 전환 경로를 사용하게 설계.
5. 첫 방문자는 기존 관심도 화면으로, 이미 설정한 사용자는 기존 피드로 이동할지 확정. 이 인트로의 시연 값은 사용자 설정에 저장하지 않기.
6. 로드 실패·타임아웃·재생 불가·Rive 종료 이벤트를 처리. 포커스·스크롤 복구 포함.
7. `prefers-reduced-motion: reduce`면 정적 최종 이미지/아트보드를 사용하고 자동 모션을 생략.
8. 실제 모바일·PC에서 안전영역과 종료 전환을 검증. 업로드·배포는 별도 승인 후 수행.

RML/로컬 `.riv`/PNG 렌더는 로그인 없이 검증합니다. Editor용 `.rev` 내보내기는 Rive 로그인이 필요해 수행하지 않았습니다.
공개 Rive 페이지 게시도 수행하지 않았습니다. 위 웹 UX와 테마 연동은 가능한 설계이며 현재 구현 완료 기능으로 주장하지 않습니다.

## 검증 결과

- 공식 Rive 1.8.0 `--verify`: 오류·경고 0. `inspect --summary`: problems 없음.
- 실제 사이트 `calculateAllocation()`을 격리된 Node VM에서 실행해 RML의 76개 조절 상태와 대조, 모두 일치. Dark/Light의 표시값 키프레임도 동일함을 검사.
- 실제 렌더 픽셀에서 흰 원형 손잡이가 관심도에 맞는 위치로 이동하는지 확인.
- 360×640, 390×844, 430×932 모바일 확인 이미지와 PC contain 확장 예시 생성. 이는 정적 레이아웃 검토이며 브라우저 연결 기능 검증은 아님.
- 테마 카드 위 본문 대비: 다크 17.06:1, 라이트 17.85:1. 보조 텍스트 대비: 다크 6.96:1, 라이트 4.76:1.
- 기존 사이트 `npm run build` 성공. 기존 번들 크기 경고만 존재.
- V2 RML·MP4·GIF 해시 동일, 기존 사이트 HTML/CSS/JS·사용자 설정·Firebase 설정·의존성 파일 변화 없음.

최종 MP4 실측: 1080×1920, 60 FPS, 270프레임, 4.500초, 580,143바이트. 다크 GIF 702,505바이트, 라이트 GIF 427,600바이트. 두 GIF 모두 540×960, 20 FPS, 90프레임, 4.500초.
