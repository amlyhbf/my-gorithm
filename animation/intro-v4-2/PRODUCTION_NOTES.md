# V4.2 제작 메모

이번 버전은 V4.1의 16초·5개 장면·모바일 9:16·두 테마를 유지한 정밀 수정이다.
운영 사이트는 연결하지 않았으며 실제 추천/저장/북마크/콘텐츠/Firebase 코드는 수정하지 않았다.

## A. 모핑의 내부 리듬

| 구간 | 국면 | 바꾼 이유와 방법 |
| --- | --- | --- |
| 6.00–6.95초 | 접근·응집 | 넓게 움직이던 관심사를 작고 밀도 있는 묶음으로 모으며 잠시 압축. 처음부터 긴 리본으로 늘어나지 않음 |
| 6.95–8.25초 | 한 번의 큰 펼침 | 반복되는 굽힘 펄스를 하나의 강조 동작으로 교체. 공부·취미는 곡선 펼침, 기술은 반대쪽부터, 문화는 둥근 압축 뒤 평탄화 |
| 8.25–10.00초 | 비대칭 정돈·정착 | 앞·뒤의 시간차를 줄이고 곡선을 편 뒤 조절 손잡이와 트랙에 도착. 정돈 후 파동을 다시 만들지 않음 |

V4.1의 같은 8개 CubicDetachedVertex 본체를 계속 사용한다. 도형을 숨긴 뒤 다른 트랙으로 교체하지 않는다.
각도·핸들·두께를 같이 계산하고 C1 값 베지어로 연결했다. 실제 유체 엔진을 사용한 것은 아니다.
0–6초의 자유 이동과 14–16초의 브랜드 화면은 수치 및 두 테마 8개 실제 RGB 비교로 V4.1과 일치함을 확인했다.

## B. 피드가 바뀌는 경험

- 숫자 중심의 `추천 12장`을 `맞춤 피드`로 변경.
- 3열×4행 작은 타일을 **2열×3행의 큰 대표 카드**로 변경.
- 기존 카드색·얇은 테두리·둥근 모서리·테마 그림자·Pretendard를 사용. 실제 콘텐츠 제목을 짧게 요약해 카드의 정체성을 구분.
- 같은 카드는 같은 Rive 객체와 고정된 제목·분야색을 유지한다. retained 카드의 문자열이나 색을 갈아 끼우지 않는다.
- 공부 관심도가 올라가면 기존 기술 카드가 내려가며 퇴장하고 실제 공부 콘텐츠가 들어온다.
- 다음 조절에서는 취미 카드가 상단으로 올라오고 기술·문화 카드가 서로 다른 곡선과 시간차로 재배치된다.
- 원본/최종 관심도는 V4.1과 동일하게 50/50/50/50 → 100/30/20/50이다.
- 10–13초 시연 키만 두 번의 읽기 쉬운 조절 동작으로 재배치했다. 전체 길이와 장면 전환 시각은 유지했다.

첫 시안에서는 세 카드가 동시에 겹쳐 제목이 가려졌다. 취미는 먼저 상단에 도착하고, 기술은 위쪽·문화는 아래쪽 곡선으로 이동하도록 고쳤다.
재배치 도중의 짧은 겹침은 남아 있지만, 세 카드가 동시에 중앙에 쌓이는 구간을 줄였다. 반복 바운스는 넣지 않았다.

## 실제 추천 규칙과 6개 대표 카드의 관계

사이트의 기본 추천은 계속 **12개**다. 영상의 6개는 제작용 대표 미리보기이며, 서비스에 새 6개 설정 기능을 추가한 것이 아니다.
실제 `calculateAllocation`과 `buildFeedList`를 격리된 Node VM에서 12개/6개 용량으로 각각 계산했다.
6개 목록은 실제 12개 목록의 일부이며 선택된 콘텐츠의 상대적 순서도 원래 추천 순서를 따른다.
작은 카드 수의 정수 반올림 때문에 6장의 색 비중이 전체 백분율과 정확히 같지는 않다. 정확한 비율은 슬라이더 옆 표시다.

실제 함수는 분야를 관심도 내림차순으로 정한 뒤 분야별 콘텐츠를 교차 배치한다.
그래서 공부만 상단에 몰아넣는 임의의 정렬은 만들지 않았다. 공부는 대표 카드가 2→3개로 늘고,
기술·문화 관심도가 내려가면 실제 규칙에 따라 취미가 위로 올라오는 모습을 보여준다.
실제 콘텐츠 ID와 순서, 21개 관심도 상태는 `feed-preview-snapshots.json`, `logic-snapshots.json`에 남겼다.
최종 실제 12개 배정은 공부 6 / 기술 2 / 문화 1 / 취미 3으로 V4.1과 같다.

## 확인 방법과 범위

V4.1 비교 영상은 같은 영상 시각을 맞췄다. V4.2는 조절 키의 내부 시각을 정리했으므로 중간 관심도 수치는 다를 수 있다.
첫 값·최종 값·추천 계산·전체 16초는 같다. 최종 12.7초 스틸에서 같은 최종 값으로 카드 가독성을 비교할 수 있다.

작업 중 먼저 저해상도 30 FPS 핵심 테스트를 만들고, 검토 후 1080×1920 60 FPS 최종본을 렌더링한다.
벡터 프레임은 공식 Rive CLI 1.8.0이 렌더링하고, FFmpeg는 MP4 압축·비교 배치에만 사용한다.
RML과 실제 로컬 `.riv`를 보관한다. `.rev` 내보내기는 공식 로그인 필요로 수행하지 않았고,
웹 런타임 통합·첫 방문/건너뛰기/다시 보기/오류 폴백/움직임 감소는 디자인 승인 후 별도 범위다.
