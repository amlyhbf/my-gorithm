# V4.2 검증 결과

## 범위

V4.1의 16초·5개 장면·9:16·두 테마·사이트 색·서체·최종 관심도·브랜드 화면을 유지했다.
수정 범위는 6–10초의 모핑과 9초대 후반–13초대의 피드 및 해당 시연 타이밍이다.
앞 6초와 마지막 2초는 실제 RGB 비교와 수치 비교로 V4.1 보존을 확인했다.

## 실제 추천 함수 및 카드

- `calculateAllocation`, `buildFeedList` 원문을 격리된 Node VM에서 실행해 21개 시연 상태를 검사했다.
- 실제 기본 12개와 영상용 대표 6개를 모두 같은 함수로 계산했다. 사이트의 기본 12개 추천은 바꾸지 않았다.
- 대표 6개의 콘텐츠 ID와 상대적 순서는 실제 12개 목록에도 존재한다.
- 시작 50/50/50/50, 최종 100/30/20/50은 V4.1과 같다.
- 최종 실제 12개 배정은 공부 6 / 기술 2 / 문화 1 / 취미 3이다.
- 카드 제목/분야색의 애니메이션은 0개다. 같은 객체가 이동하며, 한 카드가 퇴장하고 한 카드가 들어온다.
- 피드는 안정 시 6개, 전체 전환 중 검사한 최대 가시 카드도 6개였다. RML에는 퇴장·등장을 포함해 7개 카드 객체가 있다.
- 0.10초 뒤 교체, 0.133초 뒤 재배치가 시작된다. 실제 상태가 바뀌기 전에 결과를 미리 보여주지 않는다.

`feed-preview-snapshots.json`에 실제 함수 결과와 카드 ID, `logic-snapshots.json`에 서비스 12개 계산을 보존했다.
6개 대표의 정수 배정 때문에 카드 색 비중은 전체 백분율과 정확히 같지 않다. 정확한 비율은 슬라이더 옆 표시다.
중간 시연 키는 두 번의 조절로 정리했으므로 전후 비교의 중간 숫자는 달라질 수 있다. 시작·최종 상태는 같다.

## 모핑과 자체 수정

응집·압축 6.00–6.95초, 한 번의 펼침 6.95–8.25초, 정돈·정착 8.25–10.00초를 구분했다.
한 방향 펼침, 반대쪽 선두, 둥근 압축과 비대칭 지연을 조합했다. 반복된 유동 펄스를 하나의 강조 동작으로 줄였다.
본체는 같은 8개 CubicDetachedVertex이며 숨김 후 다른 UI로 바꾸지 않았다.

출력 RML의 6–10초를 1/120초 간격으로 검사한 1,924자세에서 자기교차가 없었다.
최대 접선 불일치는 약 0.000153도다. 공간 윤곽은 G1 범위이며 G2나 실제 유체 시뮬레이션이라고 주장하지 않는다.
폭·두께 변화 그래프는 `preview/morph-phase-curves.png`, 수치는 `preview/source-verification.json`에 있다.

첫 피드 스틸에서 세 카드가 동시에 겹쳐 제목이 가리는 문제를 발견했다.
취미가 먼저 상단에 도착하고 기술·문화가 위·아래 궤적과 시간차로 이동하도록 수정했다.
수정 후 30 FPS 짧은 테스트와 전후 비교를 만들고, 연속 프레임에서 교체·재배치·정돈 상태를 검토했다.
재배치 도중의 일부 짧은 겹침은 남아 있다. 전체 그리드가 불필요하게 흔들리는 바운스는 넣지 않았다.

## 공식 Rive 검사와 원본 보존

최종 원본의 공식 CLI 1.8.0 verify/inspect: **오류 0, 경고 0**.
두 아트보드는 Dark/Light, 60 FPS × 960프레임, oneShot이다.
이 프로젝트는 스크립트 없이 네이티브 벡터·텍스트·키프레임으로 구성된다.

모핑/피드 시연 외의 수정된 기존 수치 속성 213개를 비교했고,
0–6초와 14–16초 구간의 최대 차이는 약 0.000000000002였다.
두 테마의 1.2/5.983/14.0/15.983초 실제 Full HD 렌더 8개도 RGB 픽셀 차이 0이었다.
새 피드 글리프를 포함하려고 Pretendard 폰트를 다시 서브셋했지만 기존 장면의 모양은 그대로다.

편집 가능한 원본은 `scene.rml`과 `rive.yaml`, 폰트 두 개다.
실제 `.riv`는 `build/intro-v4-2.riv`에 있으며 1,097,426바이트다.
두 테마를 네이티브 런타임에서 18초까지 진행해 원래 최종 포스터와 RGB 차이 0을 확인했다.
Rive 웹 편집기용 `.rev`는 공식 로그인 필요로 생성하지 않았으며, 실제 웹 런타임 통합은 시험하지 않았다.

## 사이트 보호

`protected-baseline.json`에 있는 사이트 HTML/CSS/JS/데이터/Firebase/패키지 파일과 V4.1 소스·영상·런타임 해시가 모두 일치했다.
추가한 V4.2 폴더와 새 제작 도구만 작업 브랜치에서 관리한다.
운영 사이트 연결·배포·원본 저장소 수정·기존 브랜치 병합은 수행하지 않았다.

## 검토 범위와 한계

수치적으로 연속적이라는 사실만으로 시각적 성공을 판단하지 않았다. 네이티브 스틸·연속 프레임과 전후 자료도 검토했다.
실물 휴대폰에서 Rive 웹 런타임을 실행한 것은 아니다. 실제 기기 성능·로딩·반응형 배치는 사이트 연결 단계에서 검증해야 한다.
RML과 `.riv`는 곡선이 많아 커졌다. 웹 통합 시 파일 로딩과 프레임 시간을 측정해야 한다.
실제 유체·3D·셔터 블러는 구현하지 않았다. 기존 글로우와 벡터 시간차로 모션을 만들었다.
첫 방문/테마 자동 선택/건너뛰기/다시 보기/종료/오류 폴백/움직임 감소/HTML 시작 버튼은 승인 후 별도 범위다.

두 최종 영상은 중단 전에 이미 완성돼 있었다. 재개 후 원본 생성·네이티브 렌더·최종 MP4 재인코딩을 실행하지 않았다.
중단 전 MP4의 SHA-256이 그대로 유지됐고, 각 테마 960장의 Full HD PNG도 현재 환경에 모두 남아 있다.

재개 시 먼저 원본·런타임·두 MP4를 GitHub 체크포인트 커밋 `02beb70`에 보존했다.
그 뒤 기존 영상/프레임을 사용해 빠진 고해상도 비교 영상, 전후 보드, 모바일 시안, 최종 프레임 검증만 마쳤다.

디코딩된 프레임 수를 검사했고 모든 최종 MP4의 타임스탬프가 n/60과 0.000001초 이내로 일치했다.
코덱은 H.264/yuv420p이며 무음이다. 상세 수치·해시는 `final-media-verification.json`에 있다.

원시 PNG 1,920장의 크기·출처·해시는 `preview/frame-audit.json`으로 검사했다.
수정 구간인 6–14초의 480장은 테마별 새 네이티브 60FPS 렌더, 보존 구간의 480장은 V4.1의 원래 네이티브 프레임이다.
모핑 240장은 전부 서로 다른 PNG이며, 피드에는 읽기 위한 정적 유지가 포함된다. 저프레임 영상의 중복 프레임 변환은 하지 않았다.

360×640, 390×844, 430×932 두 테마를 contain 배치한 정적 시안을 생성했다.
주요 분야명·짧은 제목과 슬라이더 값의 잘림을 확인했다. 실제 휴대폰 웹 성능 검증과는 구분한다.
